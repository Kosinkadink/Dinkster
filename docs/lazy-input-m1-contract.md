## 1. Scope and vocabulary

M1 adds one execution concept: a linked input may be a **deferred edge**. The
edge is fully present in the immutable graph, validation, type checking, and
cycle checking, but it is omitted from the consumer's initial scheduling
dependencies. When the consumer's lazy hook requests the input, the scheduler
strengthens that edge and its producer cone into ordinary dependencies.

The following states remain distinct:

- **Unconnected**: no graph binding exists. An optional no-default argument is
  omitted; a schema default has its ordinary concrete value.
- **Connected, undemanded**: a deferred Link exists, but its producer value has
  not been requested. The hook and eventual node call see plain `None`.
- **Demanded value**: the hook requested the linked input and its producer
  completed or replayed from cache. The hook and node call see the value.
- **Absent**: the demanded producer executed and deliberately returned
  `core.absent`; section 8 applies the existing `on_absent` policy.
- **Skipped**, **failed**, and **cancelled** remain engine states, never data
  sentinels.

M1 is not a pure demand-driven engine. Dinkster retains whole-document validation,
selected-target reachability, deterministic ready-set scheduling, explicit
regions, typed optional outputs, resource ownership, and engine events.

## 2. Schema and wire decision

The coordinated backend/frontend contract is:

```python
InputSpec("branch", T, lazy=True)
```

The model field is `lazy: bool = False`. On the node-schema interface wire, true
is encoded on that input as `"lazy": true`; false is omitted. The fact belongs
to the input socket, not to a private compat table or a node-level list. It is
valid on static inputs and elaborated dynamic members, although M1 executes
only top-level statically declared scalar or whole-list inputs (section 9).

Identity rules are frozen:

- `lazy=true` is computation-relevant and MUST remain in `schema_signature`.
  Adding or removing it rotates the schema signature and every dependent
  execution identity.
- Under coordinated wire 16, each node wire entry changes its
  `schemaVersion`; because the current `schema_signature` includes that field,
  all node signatures and dependent caches rotate once. For schemas without a
  lazy input, every other interface byte remains unchanged.
- Wire 15 remains frozen. Its decoder treats `lazy` as an unknown field and
  discards it recursively; its encoder refuses a lazy schema rather than
  silently stripping a computation semantic.
- The graph document and Link wire do not change. Deferred status derives from
  the destination effective `InputSpec` plus a Link binding, so the same Link
  can never carry a second, drifting declaration.

Frontend generation-2 review settled the original coordinated design in decision
`0bc4d7f1-a645-45b7-b89d-4d4feaf6f012`. The current frontend renders lazy
inputs as ordinary sockets and performs no selector synthesis, pre-pruning,
prediction, or topology change.

Rejected alternatives:

- A private compat-only lazy table would hide behavior from native packs,
  schema identity, workers, and clients.
- A node-level list duplicates the input interface and becomes ambiguous after
  dynamic elaboration.
- Marking the graph Link itself lets the document contradict the schema.

Supported scalar V1/V3-mapped hooks preserve lazy metadata and run through M1,
including coroutine functions and synchronous hooks that return awaitables.
Stored `ComfySwitchNode` remains the physical-pruning fast path. List-mapped,
rawLink, accept-all, dynamic-expansion, and alternate-body surfaces retain their
classified refusals.

## 3. Graph and planning invariants

The implementation derives an internal deferred-edge view for each effective graph
level. Each entry carries source node/output, destination node/input, and
`deferred: bool`. This is planner data, not a new graph document type.

These invariants are frozen:

1. Graph snapshot and schema generation are pinned before elaboration.
2. Every edge, including a deferred edge that is never demanded, is checked for
   source/output existence, type compatibility, and static cycles.
3. Full-document validation still fails on errors outside selected target
   reachability, matching today's contract.
4. Static cycle detection traverses all edges. A cycle hidden entirely behind
   an undemanded branch is still `error[cycle]`; laziness is not a cycle escape.
5. Initial target reachability and ready-set dependencies traverse ordinary
   edges only. Target nodes themselves and their ordinary producer cones enter
   the initial active set.
6. Strengthening a deferred edge adds its producer and the producer's ordinary
   cone to the active set. A producer with its own deferred inputs reaches the
   same hook protocol when it becomes ready.
7. Existing produced or cached values satisfy a strengthened edge without
   re-execution, but cannot become visible to the consumer before demand.
8. Each newly activated node type is prepared through the pinned worker before
   dispatch. Preparation stays idempotent.
9. Scheduling order affects only wall-clock time. Input visibility, normalized
   requests, demand events, and results are schedule-independent.

The `run_started.detail.planned` list remains the deterministic initial strong
plan. Deferred additions are narrated by the `lazy_demand` event in section 7;
the original list is not rewritten after publication.

## 4. Deterministic hook view

The hook runs only after every ordinary dependency of the consumer is ready.
Its keyword argument shape is rebuilt from the immutable graph snapshot and the
cumulative demanded set on every round:

| Binding | Hook argument |
| --- | --- |
| ordinary Link | resolved value |
| ordinary literal | literal value |
| scalar lazy Link, not demanded | `None` |
| whole-list lazy Link, not demanded | `(None,)` |
| lazy Link, demanded and satisfied | resolved value |
| lazy-declared literal | literal value |
| unconnected optional, no default | keyword omitted |
| unconnected/defaulted | concrete schema default |

The eventual execute call receives the same shape from the final round:
undemanded connected scalar links are `None`, undemanded connected whole-list
links are `(None,)`, omitted inputs remain omitted, and defaults remain
defaults. This is the compatibility-critical distinction that prevents an
undemanded connection from silently becoming an unconnected/default input.

Visibility depends only on the demanded set. A producer that happened to run
for another consumer, a warm cache entry, single-flight completion, serial vs
parallel scheduling, or ready-set order does not expose a connected lazy value.
Once requested, those mechanisms may satisfy it without executing again.

M1 does not expose an internal sentinel to hook code. `None` deliberately
matches ComfyUI's hook convention. A hook that needs to distinguish an accepted
absence from an undemanded edge is outside M1; the scheduler still distinguishes
them internally for termination and attribution.

## 5. Bounded demand fixpoint

For a consumer with connected deferred input ids in schema order:

1. Start with an empty demanded set and build the deterministic hook view.
2. Invoke `check_lazy_status` through the worker protocol in section 6.
3. The sync hook must return a list or tuple. Every element must be a string.
4. Validate every requested id before changing scheduler state:
   - it must name an effective input;
   - the input must be declared lazy;
   - its graph binding must be a Link, not a literal, default, or omission.
5. Normalize valid results by de-duplicating and ordering in effective schema
   input order. Hook return order never changes scheduler order or event bytes.
6. `new = requested - demanded`. If `new` is empty, the node is ready to
   execute. Returning `[]`, repeating only satisfied names, and returning
   duplicate satisfied names all terminate.
7. Otherwise add `new` monotonically to demanded, emit the waiting event, add
   each producer cone as an ordinary dependency, and restage the consumer.
8. When all added producers settle, rebuild the view and run another round.

Every waiting round adds at least one member of a finite set. Therefore there
can be at most N waiting rounds for N connected deferred inputs, followed by at
most one ready round. There is no numeric retry limit and no hook-controlled
way to remove demand. A requested producer that returns `core.absent` is still
satisfied; repeated requests cannot loop.

Request failures are consumer failures with these stable diagnostic codes for
the fixture/oracle boundary:

- `lazy-request-invalid`: a returned member is not a string.
- `lazy-request-unknown-input`: no effective input has that id.
- `lazy-request-non-lazy`: the id names an ordinary input.
- `lazy-request-literal`: the lazy-declared input is bound to a literal.
- `lazy-request-unconnected`: the lazy input is omitted or defaulted.

The eventual NodeError message must name the requested id and cause. Validation
is atomic per round: one invalid request adds no edges from that round.

This strictness is an intentional Dinkster compatibility delta from pinned
ComfyUI. Its `execution.py` filters non-string requests and names already
present in the hook view before strengthening; consequently non-lazy connected
inputs, literal/default inputs, and already satisfied inputs are silently
ignored there. Dinkster still terminates normally on already satisfied names, but
fails non-string, non-lazy, literal, and defaulted-unconnected requests as
author contract errors. Unknown and omitted-unconnected names fail in both
engines. A third-party hook that unconditionally returns an inapplicable input
name can therefore run on ComfyUI and fail on Dinkster; compat does not promise to
repair that hook. The stricter validation makes invalid demand observable and
keeps scheduler state independent of incidental input presence.

## 6. Worker-bound hook protocol and routing

The implementation adds explicit protocol types rather than calling node code
directly in the host engine:

```text
LazyStatusInvocation
  request_id
  node_id
  node_type
  available_inputs: Mapping[input_id, Value]
  connected_undemanded_inputs: tuple[input_id, ...]
  effective_schema
  executor / arm / expected_execution_identity
  extension_snapshot_digest

LazyStatusResult
  requested_inputs: tuple[str, ...] | None
  error: NodeError | None
```

`Worker.check_lazy_status(request, on_event=None)` is async as transport, just
like `Worker.invoke`. The node hook may return its result directly or return an
awaitable. The worker resolves available envelopes, inserts `None` for the
explicitly connected undemanded ids, omits truly unconnected no-default kwargs,
calls the wrapped node's `check_lazy_status`, awaits an awaitable result while
the pack and execution contexts remain active, and then validates only the
outer result shape. The host owns request-name/link validation because it owns
the graph.

Run admission pins one `ExecutionRuntime`, schema mapping, extension snapshot,
and worker catalog generation. Every hook round and eventual invocation travels
through that exact runtime. The default/owner body controls lazy demand for all
dispatch arms. Execution selection happens after lazy resolution, so the owner
hook must account for ordinary provider selectors that change which inputs an
alternate body needs. An owner hook may inspect a resident input produced by
another arm only when both arms share one residency domain; final invocation
still requires exact producer-arm affinity for resident inputs.

The initial guarantee is pure and stateless:

- The hook result is a deterministic function of its arguments.
- It performs no IO, mutation, progress reporting, resource acquisition, or
  user-visible side effect.
- Rounds have no instance affinity. The same Python object is not guaranteed
  between rounds or between hook and execute.
- A hook may inspect ordinary/demanded values but may not retain them.

These restrictions cannot be inferred safely from arbitrary Python. Compat
translation documents the contract and keeps stateful/side-effecting hooks an
explicit refusal when identified; violating native hooks are author contract
errors. Ecosystem census found no multi-round stateful hook use, so this is the
smallest compatibility-bearing surface.

An `async def check_lazy_status` and a synchronous hook returning an awaitable
share the same worker path. Ordinary exceptions become `lazy-hook-failed` with
their traceback. Cancellation and other `BaseException` subclasses are not
converted to node failures: cancellation propagates through the awaited hook so
its `finally` cleanup runs before a later retry.

## 7. Events, errors, cancellation, and attribution

M1 uses the existing droppable `node_event` envelope. After each valid hook
round the engine emits event name `lazy_demand` on the consumer node with:

```json
{
  "round": 1,
  "status": "waiting",
  "requestedInputs": ["on_true"],
  "newInputs": ["on_true"],
  "demandedInputs": ["on_true"],
  "producerNodes": ["branch_source"]
}
```

Arrays use effective schema order except `producerNodes`, which is sorted and
deduplicated. `status` is `waiting` when `newInputs` is non-empty and `ready`
otherwise. The event is observability only; correctness never depends on its
delivery. Invalid results and hook exceptions emit no successful demand event.

Attribution rules:

- Hook exception, malformed result, or invalid request: `node_failed` and
  NodeError name the lazy consumer. Message prefix: `lazy-hook-failed:` or one
  of the `lazy-request-*` codes from section 5, as applicable.
- Demanded producer failure: the existing NodeError and `node_failed` name the
  producer. The consumer is not blamed and does not execute.
- Static cycle: graph validation fails before `run_started` or any hook.
- Cancellation while the hook transport or a demanded producer is pending
  propagates `CancelledError`, cancels newly owned work under existing TaskGroup
  and single-flight rules, emits no synthetic `node_failed`, and emits no
  `run_finished`. A healthy coalesced owner remains shielded exactly as today.
- `node_started` for the consumer remains the actual execute/cache-miss start,
  not a hook round. Hook activity is visible only through `lazy_demand`.

## 8. Existing semantics and feature interactions

### Stored Boolean lowering

Stored-Boolean selectors continue to lower and physically prune their inactive
exclusive cone before validation/preflight. They do not reach M1. A linked or
computed selector no longer lowers once the implementation lands; compat emits
lazy metadata and it reaches M1 instead. Eagerly evaluating both branches is
never a fallback.

### Partial targets

Only a lazy consumer in the selected target's initial strong closure runs its
hook. Excluded consumers and their deferred cones do nothing. Multiple targets
union their strong closures; a producer demanded by one path may satisfy
another path only after that other consumer independently requests its edge.
Whole-document validation, including cycles, still precedes target execution.

### Optional outputs and `core.absent`

An undemanded edge has no value and is not absent. If a demanded producer
returns `core.absent`, the existing destination `on_absent` policy runs before
the next hook round:

- `skip` skips the consumer with root provenance.
- `fail` fails at the consumer input and names the producer origin.
- `omit` restores the ordinary omitted/default shape.
- `accept` supplies plain `None`.

The demanded set still records that edge as satisfied, so an accept-None hook
cannot create an infinite re-request. `core.absent`, skip propagation, and
their current cache behavior are unchanged.

### Cache behavior

M2A replaces M1's conservative lazy-consumer bypass after the bounded hook
reaches its final demand set. The identity uses the existing schema, extension,
executor, type-stamp, and visible-value fingerprint components, plus a distinct
length-framed component containing the schema-ordered ids of every connected
lazy input that remains undemanded. Therefore connected-undemanded `None`
cannot alias omission, a schema default, or a truly unconnected input, while a
producer value that was never demanded cannot churn the consumer's identity.

The hook still runs before every cache lookup. An idempotent lazy consumer then
uses the ordinary cache hit validation, dead-owner/resource checks, put, and
single-flight owner/waiter/takeover path. Concurrent runs evaluate their hooks
independently and coalesce only the body after both reach the same final
identity. Non-idempotent lazy consumers bypass lookup, put, and single-flight;
compat `IS_CHANGED` remains conservatively translated as non-idempotent, so
M2A claims no `IS_CHANGED` parity. Explain-miss events carry structured current
and previous connected-undemanded sets and report `lazy-state-changed` instead
of misclassifying that identity transition as eviction.

Demanded producer nodes keep their existing cache behavior. Warm or incidental
producer results remain hidden until demand and may then satisfy the edge.

### Regions and lists

Exact whole-list inputs declared by V1 `INPUT_IS_LIST` or V3 `is_input_list`
use the same fixpoint: connected-undemanded values project as `(None,)`, and
demanded values arrive as one complete ordered list. Explicit map, fold, and
while bodies run an independent fixpoint for every iteration occurrence. A
fold or while decision sees that iteration's current state; parallel map
iterations keep separate demand sets and diagnostics. Unselected producer
cones, including nested regions, neither prepare nor execute. Dynamic-family
lazy members use the same occurrence-local behavior after elaboration. Hooks
participating in implicit per-element list mapping and blocker-in-list behavior
remain outside this contract.

M2A preserves the pre-execution state classes already decided: static, valid
cached/idempotent, stale/invalidated, and runtime-only/unknown. No UI may
present a stale or merely plausible branch as certain.

## 11. Implemented M1 vertical slice

### Slice A: schema and compat declaration

The coordinated wire-16 slice updates:

- `packages/dinkster-schema/src/dinkster_schema/model.py`: `InputSpec.lazy` validation.
- `packages/dinkster-schema/src/dinkster_schema/wire.py`: agreed field/version and
  signature behavior.
- `packages/dinkster-compat-comfy/src/dinkster_compat_comfy/translate.py` and
  `translate_v3.py`: preserve supported scalar lazy metadata; retain all
  explicit M1/M2/M3/M4 refusals.
- `packages/dinkster-graph/src/dinkster_graph/lower.py`: route computed selectors to
  M1 while retaining stored selector pruning.

Under wire 16, no existing schema without lazy inputs changes except the
intentional `schemaVersion` and resulting signature/cache rotation described in
section 2. Mixed versions follow the decoder-first negotiation matrix; no
silent downgrade strips laziness.

### Slice B: protocol and workers

Updated:

- `packages/dinkster-protocol/src/dinkster_protocol/__init__.py`: immutable
  `LazyStatusInvocation`, `LazyStatusResult`, and Worker method.
- `packages/dinkster-workers/src/dinkster_workers/in_process.py`: scalar hook call,
  awaitable handling, and context lifetime across suspension.
- `packages/dinkster-workers/src/dinkster_workers/boundary.py`, `isolated.py`,
  `host.py`, and transport tests: versioned request/reply frames, exact schema
  and Value codecs, cancellation, and malformed reply refusal.
- dispatch facade: default/owner-body routing only, with an exact refusal for an
  alternate selected arm.

The engine never calls node hook code directly: in-process execution crosses
the worker facade, and isolated execution stays in the worker process. Existing
workers that do not advertise the new protocol fail admission for a lazy
schema; ordinary nodes remain interoperable.

### Slice C: planner and engine kernel

Updated:

- `packages/dinkster-engine/src/dinkster_engine/engine.py`: cumulative demanded set,
  hook rounds, producer-cone activation/restaging, cancellation/attribution,
  `lazy_demand` events, and final undemanded argument shape. M2A follows this
  unchanged fixpoint with demand-aware idempotent cache identity and ordinary
  single-flight behavior.
- engine/protocol reporting tests: exact event and NodeError shapes.

The implementation keeps this as one narrow vertical slice so no schema
can advertise lazy behavior without the worker and scheduler support required
to execute it.

### Non-goals

M2A does not add `IS_CHANGED` parity, raw blockers, Region/per-element lazy
mapping, rawLink, accept-all, dynamic expansion, UI prediction, native
control-flow IR, speculation, or distributed execution changes. Those
M3/M4/later boundaries and their existing revival triggers remain unchanged.
