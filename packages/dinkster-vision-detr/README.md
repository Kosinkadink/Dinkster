# dinkster-vision-detr

`dinkster-vision-detr` is the separately installable DETR execution provider for
`dinkster.detection.detect`. It runs in an isolated pack worker, uses the
digest-pinned DETR ResNet-50 COCO checkpoint declared in `dinkster-pack.toml`,
and detects the 80 annotated COCO classes on CPU.

The checkpoint is read only through `dinkster_api.v1.declared_asset`; execution
never downloads it. Dinkster preflight presents the exact artifact need and
acquires it only with user consent. The pinned 166,618,694-byte artifact has
SHA-256 `e632da11ec76ae67bac2f8579fbed3724e08dead7d200ca13e019b197784eadc`.
It is sourced from the Apache-2.0 licensed facebookresearch/detr release URL
recorded beside it in `dinkster-pack.toml`.

The prompt input acts as a case-insensitive COCO class-name filter. Prompt mode
controls whether commas separate class names or remain literal; an empty prompt
keeps every class, and names outside the class set match nothing. Each input
frame is resized so its shortest side is 800 pixels (capped at 1333 on the
longest side) with bilinear antialiased resampling and ImageNet normalization,
then decoded by DETR's NMS-free set prediction. Detections are ordered by
descending score within each frame, batch frames concatenate in order, and
boxes are clipped to the frame bounds. `max_results` applies independently per
frame. The default count mode treats -1 as unlimited and nonnegative values as
caps. Slice-stop mode applies the value as a Python slice stop, including its
negative-index behavior, for source-compatible imports.

Backbone, positional encoding, transformer, prediction heads, and the
softmax/box postprocess match facebookresearch/detr commit
`29901c51d7fe8712168b8d0d64351170bc0f83e0`. The parity vector in
`tests/goldens/detr_r50_29901c5.json` is generated by
`tools/gen_detr_golden.py`, which refuses any modified reference checkout or
reference HEAD other than that commit. Generation uses Python 3.12 with
NumPy 2.5.1 and the torch 2.13.0 CPU wheel declared by the provider and CI
environment. The generator and exact-vector test use one torch intra-op
thread; ordinary provider execution retains the process's thread settings.
