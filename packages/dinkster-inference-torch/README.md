# dinkster-inference-torch

The torch half of Dinkster's native inference stack.
The torch-free packages (`dinkster-inference`) decode LoRA files into
typed specs, classify patch layouts, and plan/detect; this package
owns the actual tensor work: adapter weight calculation,
materializing source-key specs into live adapters/patches,
PatchSet application with backup/restore, storage-dtype writeback via
seeded stochastic rounding, native scaled-fp8 weight storage, the
cast-at-use core, device residency / memory governance, and the native
components shipped so far: tiled
codec execution, the SD/SDXL AutoencoderKL, the SD1/SDXL CLIP
text models, the SD1/SDXL diffusion UNet, the SD1.5 TAESD and SDXL
TAESDXL codecs, the classic Flux dev/schnell diffusion transformer,
the Wan 2.1 1.3B/14B T2V, FlowRVS 1.3B mask, 14B I2V, Animate2 14B,
SCAIL/SCAIL2 14B, InfiniteTalk/MultiTalk 14B, and 1.3B/14B VACE runtimes with
UMT5-XXL, CLIP ViT-H vision conditioning, Chinese base or large Wav2Vec2 audio,
and causal RGB or mask 3D VAEs, the Wan 2.2 TI2V 5B runtime with its 16x-spatial
causal VAE, 14B high/low-noise composition, Bernini 14B context conditioning,
and 14B Animate pose/face conditioning against Wan 2.1 latent geometry,
and the per-component MiniMax H3 runtimes for its Qwen3-VL conditioner,
FL2VA/REF2VA DiTs, and video/audio codecs, plus independently loaded SeedVR2
3B/7B diffusion and causal VAE components for image and video restoration.

Everything here is a near-transcription of ComfyUI reference code at
the audited baseline (`b78cec87`, see `docs/native-inference-plan.md`
section on the torch-free boundary), or at the newer exact commit named
by a profile-specific executed golden. Ported tensor code deliberately
stays close to the source so upstream fixes remain easy to port.
Oracle goldens are generated by RUNNING the reference implementations
(`tools/gen_adapter_goldens.py`, `tools/gen_patch_goldens.py`). OFT/BOFT
constraint cases pass the trainer's effective `alpha * out_dim` bound into
the pinned reference while retaining raw alpha in the recorded adapter data.

## Training API

The separately versioned training runtime consumes package-root exports only.
Its supported surface is `AttentionGuidanceContext`, `MiniMaxH3AudioVAE`,
`MiniMaxH3ConditionerModel`, `MiniMaxH3DiTConditioning`,
`MiniMaxH3KeyframeLatent`, `MiniMaxH3ReferenceKind`,
`MiniMaxH3ReferenceLatents`, `MiniMaxH3VideoVAE`,
`MiniMaxH3VideoVAEConfig`, `MiniMaxMusic3TextModel`,
`QwenImageLanguageModel`, `QwenImageTextModel`,
`SD15AttentionExecutionContext`, `Wan21Model`, `Wan21MultiTalkExecution`,
`Wan21TextRuntime`, `Wan22VAE`, `WanAttentionBlock`, `WanVAE`, `WanVAEConfig`,
`assemble_minimax_h3_dit`, `bind_fp8_matmul_layer`, `load_tensors`,
`minimax_h3_audio_vae_runtime_identity`,
`minimax_h3_conditioner_runtime_identity`,
`minimax_h3_video_vae_runtime_identity`, `plan_minimax_h3_model_assembly`,
`select_attention`, `simple_schedule`, `tokenize_music_prompt`, and
`worker_planning_context`. The numerical and model implementations remain in
this package rather than being copied into training.

## Layout

- `tensor_ops.py` - shared helpers: `cast_to_device`,
  `pad_tensor_to_shape`, `weight_decompose` (DoRA).
- `adapters.py` - one class per `comfy/weight_adapter/*` variant:
  LoRA (incl. LoCon mid + reshape), LoHa (incl. Tucker), LoKr (full,
  decomposed, Tucker), GLoRA (old + new orientation), OFT, BOFT.
  `calculate` mutates and returns `weight` exactly like the
  reference; the caller owns copying.
- `materialize.py` - stage-4a decode specs (SOURCE-key references) +
  a tensor mapping -> adapter instances / typed patch values / a
  whole `PatchSet` (`materialize_adapter`, `materialize_value`,
  `build_patch_set`). Owns the reference scalar-read semantics
  (`.alpha` via `.item()`, `.reshape_weight` via `.tolist()`).
- `apply.py` - `apply_patches`, the typed port of comfy/lora.py
  `calculate_weight` (sequential entries, offsets, strength_model,
  nested patches incl. the donor `convert` hook, diff/set/
  model-as-lora with the per-entry `function` delta hook, adapter
  dispatch), plus `patch_weights`/`restore_weights`: intermediate-
  dtype copy (or fp8 dequantize), apply, write back to the original
  storage form with the per-key seed (stochastic rounding for plain
  tensors, scale-recalculating requantization for fp8 stores),
  exact-original backup with rollback on failure.
- `rounding.py` - `stochastic_rounding` + `string_to_seed`
  (comfy/float.py + comfy/utils.py CRC seed). Prefers the
  dinkster-kitchen accelerated fp8 kernel when the installed
  dinkster_kitchen exposes it (capability probe, never a version check)
  and falls back to the reference's manual torch path. Stochastic
  rounding is LOAD-BEARING for fp8/quantized storage: plain nearest
  rounding erases sub-ulp LoRA deltas; the stochastic path preserves
  them in expectation (pinned by
  `test_rounding_preserves_small_delta_in_expectation`). One
  deliberate divergence: the manual path computes the exponent with
  exact `torch.frexp` instead of the reference's fp16 `log2`, whose
  rounding-up just below powers of two lands results off the fp8
  grid (docs/comfyui-issues/stochastic-rounding-fp16-log2-boundary.md;
  boundary regression in `test_patches.py`, kitchen eager-vs-CUDA
  canary in `test_gpu.py`).
- `quant.py` - `Fp8ScaledWeight` (fp8 qdata + float32 per-tensor
  scale + compute dtype) with `quantize_fp8_scaled` /
  `requantize_fp8_scaled`, transcribed bit-exact from
  comfy/quant_ops.py `_TensorCoreFP8LayoutBase` + dinkster-kitchen's
  eager kernels. A plain frozen value type, not a torch wrapper
  subclass: storage form stays visible at every use site.
- `ops.py` - `cast_weight`, the cast-at-use pipeline
  (comfy/ops.py cast_bias_weight order: move at storage dtype ->
  cast/dequantize to compute dtype -> deferred functions on an owned
  buffer) over explicit inputs, and `DeferredPatch` (the reference's
  LowVramPatch: patches applied at cast time, intermediate pinned to
  the weight's own dtype). Keep calls to this outside torch.compile
  regions; the compute consuming its output compiles cleanly
  (pinned by `test_compiled_consumer_parity`).
- `memory.py` - device-memory introspection + the reserve policy
  (comfy/model_management.py get_free_memory / get_total_memory /
  minimum_inference_memory / soft_empty_cache). Effective CUDA free
  memory = driver-free PLUS the torch allocator's reclaimable reserve
  (`reserved - active`); physical headroom, inference working reserve,
  and per-device hard budgets become one injected `MemoryPolicy` value
  instead of import-time globals. Raw CUDA introspection stays reference-
  exact; residency alone projects free bytes into the operator budget.
  MPS is one shared physical pool: its effective total and available
  bytes are the minima of the system-memory view and Metal's recommended
  working-set capacity/headroom. cuda/cpu/mps only; other device types
  raise loudly (ROADMAP).
- `residency.py` - which weights live on the load device, and who
  decides. `ResidentWeights` is one model's placement mechanism
  (ModelPatcher load/partially_load/partially_unload): key-group
  units settle largest-offload-estimate-first under strict-< byte
  budgets; a resident patched key holds PATCHED storage with the
  exact original kept as backup; an offloaded patched key stays
  pristine. Ordinary values patch at cast time via `DeferredPatch`;
  packed INT8/NVFP4 values patch and requantize on demand to retain
  quantized execution. Budgets are real ints (`None` = unlimited),
  not the reference's 0.1/1e32 float sentinels. `ResidencyManager` is the fleet policy
  (load_models_gpu/free_memory): MRU registry, 1.1-inflated
  free-ahead-of-load, the verbatim low-VRAM budget formula, eviction
  ordered most-offloaded/smallest/newest with
  partial-unload-before-detach - all over explicit injected state
  (`MemoryPolicy` + injectable free-memory/empty-cache functions), no
  process-global registry. The manager consumes models only through
  the `ResidencyMechanism` protocol. CUDA pageable-to-device transfers reuse a
  fixed 96+32 MiB pinned ring per device. Each materialized slot participates in
  the shared physical-storage and CUDA-registration ledgers, can be shed safely
  after its completion event, and uses the synchronous pageable path when
  pinned memory is disabled or live headroom refuses the slot.
- `paged_kv.py` - fixed-block key/value storage for generation sessions,
  with transactional append, copy-on-write prefix sharing, active pins,
  idle LRU reclamation, and optional bounded host offload.
- `qwen_generation.py` - pull-based Qwen3-0.6B and Qwen3-30B-A3B token
  generation with ordered sampler chains, incremental UTF-8 decoding, and
  commit-or-rollback sessions over the paged KV store. Active requests use one
  contiguous working cache, matching ComfyUI's allocation strategy without
  reallocating the prefix on every decoded token.
- `qwen_generation_scheduler.py` - an opt-in continuous provider over the same
  stream/session contract. It preallocates fixed KV slots, round-robins chunked
  prefill, batches decode streams with matching cache positions, and compacts
  released slots without changing logical session ownership. Output is
  deterministic for a fixed batch composition and execution shape; BF16
  kernels do not promise bit-exact tokens across different batch shapes.
- `qwen_layer_placement.py`, `qwen_paged_kv.py` - explicit contiguous Qwen
  transformer ranges on indexed CUDA devices. The placement enrolls one weight
  mechanism per device and partitions transactional KV by range, so direct and
  continuous generation keep each layer's weights and cache local while moving
  hidden activations only at range and tied-output boundaries.
- `module_residency.py` - transactional assembly enrollment and the
  compute-following storage policy. Eligible patched components apply their
  immutable PatchSet once to owned fp32 state, cast once to authoritative
  fp16/bf16 registrations, then construct all mechanisms and bind all owners.
  Tied Parameters retain identity; ambiguous tied targets and overlapping
  distinct views refuse before mutation. Preparation, factory, and bind
  failures restore exact original registrations and unload prior mechanisms.
  Quantized, mixed, and unsupported storage keeps its existing patch path.
  `enroll_component_placement` applies the same ownership transaction to
  disjoint module subtrees assigned to explicit devices and refuses tied state
  split across mechanisms.
- `tiling.py` - `tiled_apply`, the tensor half of tiled codec
  execution (comfy/utils.py tiled_scale_multidim's accumulation
  loop): allocate output + weight accumulator, run the function per
  tile from a torch-free `TilePlan` (dinkster_inference.tiling),
  feather-mask, accumulate, normalize. No
  `inference_mode`/`no_grad` baked in (training program); an
  uncovered output region raises `TileApplyError` instead of
  dividing into NaNs. Golden-pinned against executed reference
  outputs (tests/goldens/tiling_goldens.json).
- `codecs.py` - `CodecPlugin`: a `CodecDescriptor` bound to concrete
  encoder/decoder implementations (+ optional memory estimator).
  Registers in a `Registry[CodecPlugin]` - no central family switch.
  Direct and tiled encode/decode; tiled 2D runs the reference's
  three-aspect-ratio seam-hiding sweep (comfy/sd.py decode_tiled_/
  encode_tiled_), 1D/3D run one pass, defaults come from the
  descriptor's `CodecTiling`. Optional `content_in`/`content_out`
  hooks are the codec's whole-content transforms (comfy/sd.py
  process_input/process_output): applied ONCE per call, around
  direct execution or the complete tiled composition - never per
  tile, so tile seams see untransformed values. The optional
  `content_crop` hook (comfy/sd.py vae_encode_crop_pixels) runs
  first on both encode entry points and may change spatial extents
  (center-crop to the downscale grid), so tile planning always sees
  the final shape.
- `operations.py` - the Operations seam: typed layer factories
  threaded through native architecture constructors (the reference's
  comfy/ops.py `operations` class-namespace parameter, as a
  protocol). `INITLESS` is disable_weight_init - stock torch layers
  with parameter init skipped, for checkpoint-loaded models.
  `CastOperations(dtype)` is the reference's manual_cast: parameters
  keep whatever dtype the checkpoint shipped (state-dict layout
  unchanged), and every forward casts them through the stage-4c
  `cast_weight` pipeline to the bind-time compute dtype - how
  fp16-STORED text encoders run at fp32 COMPUTE (T5-XXL activations
  overflow fp16; the reference forwards its text encoders at fp32
  over fp16 storage for the same reason). Module-held
  `Fp8ScaledWeight` storage is ledgered (ROADMAP "Cast-at-use
  Operations: fp8 module storage wiring"). Implementations must
  resolve cast/quant config at module-bind time, never per-forward.
  Conv1d, ConvTranspose1d, and Conv3d use the same stock state-dict,
  cast-at-use, and per-forward residency lease contracts as the
  existing factories. MiniMax H3 video and audio codecs use this
  substrate in their per-component VAE runtimes; they are not registered as generic
  `CodecPlugin` product handles.
  `ResidencyRouted` is the public mixin for an external `nn.Module`
  subclass that directly owns parameters or persistent buffers. Its
  forward reads direct state eagerly while resident and, when
  `_offloaded_residency()` returns a binding, consumes that state
  inside one `binding.lease()` bracket using direct-state names and
  stored dtypes. The whole root is enrolled once with
  `enroll_component`; routed factory children retain their bindings
  and state-dict key prefixes. Re-enrolling that component root is
  refused.
- `multidevice_attention.py` - the opt-in, direct-import
  `MultiDeviceAttentionKernel`. It snapshots at least two explicit devices,
  partitions one rank-4 attention call into balanced contiguous head lanes
  through torch-free `plan_lanes`, runs an injected `AttentionKernel`
  concurrently, and gathers in original head order on the input owner device.
  It preserves autograd and plugs directly into
  `Flux(config, attention_kernel=kernel)` without changing default Flux wiring.
  The initial surface intentionally refuses masks, causal attention, explicit
  scales, GQA, concurrent calls, and calls after close.
- `minimax_h3_dit.py` - the direct-import-only MiniMax H3 DiT source. Its
  attention/provider primitive requires a roleless injected
  `AttentionKernel` and frozen exact `torch-sdpa` plus full running torch-version
  evidence, then applies the corrected 5376-to-21504 bias-free QKV projection,
  per-head 128-wide Q/K RMSNorm, split-half three-axis RoPE over the first 96
  dimensions, full unmasked noncausal rank-4 attention, and the bias-free
  7168-to-5376 output projection. Its standalone helper and production MODEL
  loading require an authenticated generic
  attention selection and preserve its provider evidence in every block. The
  per-component runtime completes the Operations-backed 532-key DiT,
  including token refinement, AdaLN/MLP/final layers, text/condition/reference/
  target packing, 1x2x2 video pad/crop, channel-major stereo audio rows, exact
  S2 audio carry conversion, and generic-control refusal. Load Diffusion Model
  loads each exact authenticated FL2VA/REF2VA artifact as a single-role MODEL
  handle. Generic multi-stream MODEL evaluation, control, and intervention sites
  remain absent.
- `minimax_h3_conditioner.py` - the direct-import Qwen3-VL-32B layer-50
  conditioner source. It preserves the exact unnormalized 902-key state,
  64x128/8x128 grouped-query language attention with interleaved M-RoPE,
  Q/K norms, the 27-layer vision tower, and DeepStack extraction/injection.
  Exact meta strict-load and reduced CPU execution are proven; tokenizer/image
  realization now uses the vendored Qwen BPE, raw non-chat presentation,
  reference-exact image/video patching, three-axis position IDs, visual masks,
  and DiT modality tags. Load CLIP loads the exact authenticated conditioner
  artifact as an H3 conditioner component.
- `seedvr2_dit.py`, `seedvr2_vae.py`, and `seedvr2_runtime.py` - the three exact
  published SeedVR2 diffusion layouts, causal 3D VAE, source-latent
  conditioning, discrete-flow custom-sampling runtime, and direct/tiled codec
  execution. `seedvr2_component.py` strictly loads either component through
  the generic diffusion-model and VAE loaders; `seedvr2_color.py` supplies the
  postprocessing color-transfer kernels.
- `minimax_h3_assembly.py` - exact header planning and strict per-component
  loading for FL2VA or REF2VA DiTs, the shared Qwen3-VL conditioner, and the
  video and audio VAEs. Loading verifies every selected
  official byte size and SHA256.
  Loading snapshots local file identity before and after all reads and assumes
  the trusted local artifact store neither mutates contents in place nor
  replaces and restores paths during one assembly call. Unit tests use
  synthetic headers, and capability-gated GPU coverage loads pinned video VAE
  artifacts for temporal FP16/INT8 parity and peak-memory validation.
- `multidevice_residency.py` - the direct-import `DeviceReplicaResidencyHost`.
  It builds and enrolls one module on one explicitly indexed device, requires
  full `ResidentWeights` residency before preparation succeeds, retains the
  module, mechanism, attention kernel, and unit runner through cancellation,
  and clears all owned references after exactly one terminal unload. Its
  attention kernel is accessible only while active and composes structurally
  with `MultiDeviceAttentionKernel` on indexed CPU aliases without claiming
  distinct physical CPU devices.
- `autoencoder_kl.py` - the native SD/SDXL AutoencoderKL:
  Encoder/Decoder/ResnetBlock/AttnBlock (SDPA)/Upsample/Downsample
  ported from comfy/ldm/modules/diffusionmodules/model.py with
  Comfy-compatible state-dict names, built from a torch-free
  `KLConfig` (dinkster_inference.autoencoder_kl detection). `encode()`
  is deterministic posterior mode (the reference default);
  stochastic encodes take an explicit generator, never hidden global
  RNG. `kl_codec_plugin` wires it into the codec registry with the
  content transforms above; canonical and Diffusers SD1.5/SDXL state
  dicts share one strict module layout, with planned rank-2 attention
  weights reshaped to canonical 1x1 convs before `load_state_dict`.
- `taesd.py` - native TAESD/TAESDXL encoder and decoder modules,
  family-specific latent scaling, VAE boundary transforms, encode
  cropping, and a `CodecPlugin`, matching comfy/taesd/taesd.py and
  comfy/sd.py @ f4b99bc. The independent halves strict-load into
  their own modules and remain distinct from the KL implementation.
- `minimax_h3_audio.py` - MiniMax H3 audio-codec source:
  the DAC waveform encoder, causal posterior projection, and alias-free
  BigVGAN decoder at the exact stereo `[B,32,2,T40]`, 32 kHz, and
  800-samples-per-frame boundary from comfy/ldm/minimax/audio_vae.py @
  2a68ce33. Reduced CPU proofs cover primitives, geometry, normalization,
  bounded remainder padding, refusal-before-model-work, and temporary
  lifetime. The per-component loader authenticates and loads the audio artifact;
  generic `CodecPlugin` registration remains absent.
  One Operations value now reaches every state-bearing audio constructor;
  convolution, transpose, linear, and normalization state uses the standard
  factories, while activation, filter, attention-bias, and latent-statistic
  state uses the public direct-owner residency contract. The exact 917-entry
  checkpoint layout, eager codec behavior, whole-root enrollment, complete
  prefetch ownership, reduced resident/offloaded encode and decode, and lease
  cleanup have focused CPU and isolated CUDA proofs. The video codec provides
  the corresponding routed source for its own architecture. Both codecs are
  supported through VAE component handles, not generic `CodecPlugin` products.
- `clip_text.py` - the native SD1/SDXL CLIP text model:
  attention/MLP/layer/encoder/embeddings/transformer ported from
  comfy/clip_model.py with Comfy-compatible state-dict names, built
  from a torch-free `ClipTextConfig`
  (dinkster_inference.clip_text detection). Causal attention via SDPA
  `is_causal=True`; activation and hidden-layer selection are
  bind-time constants (compile discipline). `ClipTextEncoder` is the
  encode_token_weights policy over the slice-3 packed chunks:
  empty-chunk batching when weights deviate, textual-inversion row
  substitution through `EmbeddingLookup`,
  `(z - z_empty) * weight + z_empty` with weight-1.0 positions
  bit-exact, first-chunk pooled, float32 outputs.
  `SD1_CLIP_L_POLICY` / `SDXL_CLIP_POLICY` capture the family knobs;
  `compose_sdxl_conditioning` is the SDXL two-tower composition.
  Mis-shaped textual-inversion vectors refuse (`ClipEncodeError`)
  where the reference warns and drops.
- `scheduled.py` - the explicit Flux/SD scheduled text producer. It
  preserves ordinary runtime methods, routes only shipped CLIP-L/CLIP-G/T5
  weighted spans or raw Ovis Qwen3-2B text, applies identified layout-bound
  worker transforms transactionally, acquires structural text/diffusion
  variants from an injected execution owner, and emits canonical TEXT/POOLED
  tensor bindings in a DMFC carrier. It does not sample schedules or
  materialize native overlays.
- `scheduled_sampling.py` - the explicit scheduled runtime sibling.
  Frozen resolver requests bind canonical DMFC bytes, runtime identity, ordered
  DIFFUSION overlays, and full stack digest to one worker generation, exact
  patch-provider snapshot/declaration, and one structural PatchSet before model
  work. FluxRuntime/SDRuntime materialize carriers once, select the immutable
  uncond tuple once, lazily stage grouped patches on the solver-created latent,
  preserve CFG/CFG++ and ordinary schedule/noise ordering, and close staging on
  success, refusal, cancellation, progress failure, or model failure. Active
  guidance extensions and scheduled SD inpaint refuse explicitly. Backend
  overlay materialization and compat activation remain separate lifecycle work.
- `regional.py` - the canonical-carrier regional conditioning consumer. It strictly
  materializes shipped Flux/SD TEXT/POOLED layouts, percent areas and F32 masks
  once per sample, then evaluates active regions on ComfyUI's deterministic
  sufficient-memory/max-concat path (one callback per region, reverse within
  each maximal compatible group), with crop views, mask or fuzz-8 multipliers,
  count-normalized overlap, and strict materialized H/W/device identity. B2.3a
  additionally decodes strict `conditioning-scale` vectors and scheduled patch
  digests, then exposes patch-isolated cond/uncond reverse/LCM groups with pinned
  reciprocal-floor memory-fit selection, one forward per subgroup, and dynamic uncond omission.
  `prepare_grouped_patches` preflights and binds the sample's materialized
  cond/uncond rows, tensor versions, latent descriptor, and sigma space before
  mapping access, then owns sample-lifetime staging across sigma evaluations.
  `scheduled_sampling.py` is its only runtime caller; ordinary sampling remains
  unchanged.
- `scaled_patches.py` - the eager-only per-condition scaling primitive. An
  explicit context completely preflights one immutable PatchSet against
  uniquely owned plain Linear weights, stages only strict full-diff or simple
  LoRA tensors, and installs transactional forward hooks that apply ordered
  per-row scales without changing base weights. Cancellation, compile mode,
  malformed calls, target/patch drift, nesting, re-entry, and same-model
  concurrency refuse with stable codes; every exit removes hooks and releases
  staging. B2.3a admits exact production Initless/Cast Linear types and adds a
  prepared execution owner that stages once, reports bytes, and swaps subgroup
  scales transactionally while preserving residency leases. B2.3b consumes this
  owner without changing its grouping or patch math.
- `unet.py` - the native SD1/SDXL 2D diffusion UNet:
  UNetModel/ResBlock/Upsample/Downsample/timestep_embedding ported
  from comfy/ldm/modules/diffusionmodules/openaimodel.py and
  SpatialTransformer/BasicTransformerBlock/CrossAttention (SDPA with
  the reference head reshape)/FeedForward/Geglu from
  comfy/ldm/modules/attention.py, with Comfy-compatible state-dict
  names (time_embed.*, label_emb.0.*, input_blocks.N.M.*,
  middle_block.M.*, output_blocks.N.M.*, out.*), built from a
  torch-free `UNetConfig` (dinkster_inference.unet detection). Conv
  (SD1) or linear (SDXL) transformer projections and optional SDXL
  ADM conditioning (`y` required iff `adm_in_channels` is set) are
  construction-time facts; the forward signature stays
  (x, timesteps, context, y). No inference_mode/no_grad and
  out-of-place residual adds (training program). Scope pins
  (ControlNet injection, transformer_options seams, video/temporal
  modes, legacy attention modes, gradient checkpointing) are in the
  module docstring with deferrals in ROADMAP "SD-era UNet
  variants". Its `Upsample`/`Downsample` stay module-scoped (not in
  the package `__all__`) because autoencoder_kl already exports
  classes with those names.
- `flux.py` - the native classic Flux dev/schnell diffusion
  transformer: Flux/DoubleStreamBlock/SingleStreamBlock/Modulation/
  MLPEmbedder/QKNorm/LastLayer/EmbedND ported from
  comfy/ldm/flux/model.py + layers.py, ND RoPE + rotation from
  comfy/ldm/flux/math.py, with the reference's bare-BFL state-dict
  keys (img_in.*, time_in.*, vector_in.*, guidance_in.*, txt_in.*,
  double_blocks.N.*, single_blocks.N.*, final_layer.*), built from a
  torch-free `FluxConfig` (dinkster_inference.flux detection) through
  the Operations seam (which gained LayerNorm-affine and RMSNorm
  factories for it). `apply_rope` prefers the dinkster-kitchen kernel
  behind a capability probe, gated on autograd facts (the kernel has
  no autograd formula) and torch.compile (pure-torch math under
  compile; inductor fuses it), with a device-context pin fixing an
  upstream multi-GPU Triton defect (docs/comfyui-issues/
  comfy-kitchen-triton-apply-rope-wrong-device.md). Deliberate
  strictness: `y` required with exactly vec_in_dim columns and
  `guidance` required iff guidance_embed, where the reference
  zero-fills/slices/skips silently. Scope pins (Kontext ref_latents,
  ControlNet injection, attention masks, transformer_options seams,
  the MPS fp64 carve-out) are in the module docstring with deferrals
  in ROADMAP "Classic-Flux variant and conditioning surface".
- `flux_window.py` - execution of already-compiled Flux packed-grid window
  plans: exact plan admission, declared window-local token layouts, global
  image position ids, ordered gathers, and deterministic tensor realization
  of the accumulation-normalize merge. Windowed model calls remain below one
  full-geometry guidance execution.
- `t5_text.py` - the native classic T5-XXL text encoder (Flux's
  second tower): T5LayerNorm/T5Attention/T5LayerSelfAttention/
  T5DenseGatedActDense/T5DenseActDense/T5LayerFF/T5Block/T5Stack
  ported from comfy/text_encoders/t5.py with reference-identical
  state-dict keys (shared.weight, encoder.block.N.layer.*.,
  encoder.final_layer_norm.weight), built from a torch-free
  `T5Config` (dinkster_inference.t5_text detection). Faithfulness pins:
  UNSCALED attention via SDPA `scale=1.0` (bit-identical to the
  reference's k*sqrt(head_dim) fold - sqrt(64)=8 is exact),
  T5LayerNorm keeps the reference's exact RMS math (variance in the
  INPUT dtype, deliberately not F.rms_norm), block 0 alone owns the
  relative-attention-bias table and later blocks reuse the computed
  bias (past_bias threading). `T5TextEncoder` is the reference

  eager-forward-only; it intentionally never claims fullgraph compile or
  delayed-backward lifetime.

`MultiDeviceAttentionKernel` is a direct acceleration source path for one
conditioning workload's Flux attention calls. The focused acceptance test runs
the existing SDPA kernel over two physical GPUs and compares value and backward
results with single-owner-device SDPA. This is correctness evidence, not a speed
claim. The direct-import replica lifecycle and persistent-residency primitive
has source/CPU/static evidence plus focused physical execution on explicit GPUs
2 and 3, proving persistent materialization, active-only attention dispatch,
cancellation retention, and terminal release. Production composition that binds
the public parent configuration and session endpoint APIs to exact replica
runtimes, ambient device discovery, recipe/payload/gather/product wiring,
observability, activation, deployment, end-to-end workload throughput
acceptance, and capability, speed, acceptance, and support claims remain open.
This path does not split CFG branches or claim acceleration from multiple
conditioning branches.

Deliberate deviations (all loud, all tested): where the reference
catches exceptions, logs, and silently leaves a weight unpatched,
this package raises (`AdapterMathError`, `MaterializeError`,
`PatchApplyError`). A LoRA that cannot be applied is a failed job,
not a silently unmodified model.

The two fp8 rounding paths (kitchen accelerated / manual torch) draw
randomness differently and are not bit-equal - not even upstream,
where both are accepted. The accelerated path's seeded uint8
`torch.randint` stream is byte-identical across the torch builds
Dinkster spans (verified 2.9.1 vs 2.13.0), so its goldens replay
bit-exact on any build; the manual path's fp16 `torch.rand` stream is
torch-build-specific (see the golden test's grid-adjacency fallback).

### dinkster-kitchen

The torch extra installs the reviewed dinkster-kitchen 0.2.35.post1 provider. The
accelerated fp8 stochastic-rounding path activates when
`dinkster_kitchen.stochastic_rounding_fp8` is importable; without it the
manual torch path is used and the kitchen golden tests skip. A
CPU environments install its pure-Python wheel from a hash-pinned PyPI URL;
GPU environments install the exact platform wheel from PyPI.

### Sol sparse attention

The opt-in `sol` attention policy uses dinkster-kitchen 0.2.35.post1's approximate,
training-free Sol CUDA kernel on NVIDIA SM80+ devices. It executes unmasked,
noncausal BF16 self-attention with equal q/k/v shapes and 128-wide heads using
`tau=1.0` and tail coverage. It trades output similarity and temporary workspace
memory for sparse-kernel speed. Other dtypes, geometries, devices, masks, causal
calls, and GQA retain their exact semantics through built-in SDPA. Automatic
routing never selects Sol; a server or job must explicitly request it.

The native Attention Schedule can switch an authenticated Sol route against
SDPA on outer sampling-step boundaries and evaluate a `dinkster.curve` for tau.
For MiniMax H3's packed `[text][condition][reference][audio][video]` sequence,
`exact_kv` keeps every block before generated video available as exact KV to
all queries. The packing layer supplies the immutable token range to the central
selector; model code does not select Sol. This sink mode fails closed on
unsupported layouts and remains unavailable with distributed scheduled attention
until rank consensus covers the realized row and layout.

### SageAttention

Automatic routing selects SageAttention when the worker authenticates this
support. Explicit Sage selection remains available. Automatic VAE attention
uses SDPA with bounded-memory OOM fallback except on ROCm, where bounded-memory
attention is primary. Explicit policies do not acquire this fallback.

MPS cannot retain fp8 tensors. Enrollment converts fp8 checkpoint

finding to investigate, never a tolerance to widen.

### Hosted-CI dispatch pins

The hosted torch-cpu CI suite pins the two torch CPU kernel
dispatchers that are pinnable on every x64 vendor
(`ATEN_CPU_CAPABILITY=avx2`, `ONEDNN_MAX_CPU_ISA=AVX2`) because
GitHub runners span CPU microarchitectures and unpinned dispatch
produces run-to-run float variance against the executed-reference
goldens (#864). oneMKL is deliberately NOT pinned - the suite leaves
`MKL_CBWR` unset, so oneMKL runs with conditional numerical
reproducibility off (`CNR:OFF`), the same state the goldens are
minted under. CNR modes other than AUTO and COMPATIBLE are honored on
Intel CPUs only; hosted evidence on PR #867 showed `MKL_CBWR=AVX2`
diverging from the goldens on dozens of tolerance tests on an Intel
runner while the same suites passed on an AMD runner that fell back
to `CNR:AUTO`. Any `MKL_CBWR` change diverges from goldens minted
under `CNR:OFF`; whether `MKL_CBWR=COMPATIBLE` would unify vendors on
freshly minted goldens is unproven (probe PR #902 collected AMD-only
samples).

The pins are necessary but not sufficient. With both pins active and
`CNR:OFF`, oneMKL's GEMM kernels still differ by CPU vendor: AMD
reproduces the goldens while Intel diverges by ~1e-5 (#900). ONNX
Runtime's MLAS dispatcher is not affected by either pin; EfficientSAM
vectors from an AMD EPYC 9V45 with AVX-512 diverged by up to 2.48e-5
from the AMD no-AVX512 golden (#1045). CI therefore runs the torch
suites only on AMD runners with AVX2 and without AVX-512.
`full-validation.yml` defines one `torch-cpu` job. Before checkout,
it checks `/proc/cpuinfo` for `AuthenticAMD`, `avx2` and the absence
of `avx512f`, failing with a CPU golden-contract diagnostic on a
mismatch. A matching runner executes the suite through the
`torch-cpu-suite` composite action. The job fails on a CPU-contract
mismatch or a suite failure; there are no retry legs or aggregate job.

Unpinned oneMKL still selects kernels
per microarchitecture, so the fixed-seed sha256 digest assertions in
test_wiring.py and test_wiring_sd.py remain machine-dependent under
these pins; they load `wiring_digests.json` through the mint-host CPU
gate and skip on other CPUs, including every hosted runner (#864; see
`golden_files.py`). Each suite leg logs the CPU model, vendor, and
engaged CNR state per run; if a golden diverges on one vendor or SKU
only, that log line is the first discriminator. Linux canonical
goldens that hosted CI compares exactly must be minted on an
AuthenticAMD host without AVX-512, with the two pinned variables set
and `MKL_CBWR` unset, and with the mint-host CPU recorded. Local gates
on other machines keep native dispatch; the platform-tuple loader
still selects by `<platform>-py<python-patch>-torch<torch-build>` only.
