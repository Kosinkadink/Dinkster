# dinkster-vision-rtdetr

`dinkster-vision-rtdetr` is the separately installable RT-DETR v4 x-HGNet
provider for `dinkster.detection.detect`. It runs in an isolated CPU worker,
loads the declared fp16 checkpoint strictly, and executes the model in
float32. It detects the 80 COCO classes.

The checkpoint is read only through `dinkster_api.v1.declared_asset`; execution
never downloads it. The immutable source URL and BLAKE3 digest are declared
in `dinkster-pack.toml`. The pinned 123,968,978-byte artifact has SHA-256
`581f9af9bbabb664d1891cbccd823308b176ecd409146f954dfa39af3bec2476`.
The source repository metadata identifies the same path, size, and SHA-256 at
commit `f122ac7976997885e3bfeab2bb3a537a6bc250bc`.

Each frame is resized directly to 640x640 with bilinear interpolation. Boxes
are restored to source pixel coordinates. The prompt is a case-insensitive
COCO class filter; prompt mode controls whether commas separate class names or
remain literal, and an empty prompt keeps every class. Detections require
scores strictly greater than `min_score`, remain ordered by descending score
per frame, and obey `max_results` independently per frame. The default count
mode treats -1 as unlimited and nonnegative values as caps. Slice-stop mode
applies the value as a Python slice stop, including its negative-index
behavior, to preserve imported ComfyUI workflows exactly.

The model architecture and inference math match ComfyUI commit
`c67885b14556cf3e4e061862925282d403d09862`. The parity vector in
`tests/goldens/rtdetr_v4_x_hgnet_c67885b.json` is generated by
`tools/gen_rtdetr_golden.py`, which requires a clean reference checkout at
that exact commit. Generation and exact parity testing use torch 2.13.0 CPU,
NumPy 2.5.1, and one torch intra-op thread; normal provider execution retains
the worker's thread settings.
